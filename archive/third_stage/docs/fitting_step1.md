# 第一步：固定時間，找回已知位移

這一步驗證計算方法，不處理真實動作分段、時間估計或 goal 數量選擇。

## 1. 先設定答案

所有位置與位移使用公尺，時間使用秒。起點固定為 `(0.20, -0.10, 0.40)`。

| 位移 | 啟動時間 | 完成時間 | XYZ 位移 |
|---|---:|---:|---|
| 第一條 | 0.20 | 2.20 | `(0.30, 0.10, -0.05)` |
| 第二條 | 1.20 | 3.20 | `(-0.12, 0.20, 0.08)` |

兩條位移在 1.20–2.20 秒重疊。以 120 Hz 產生 0–3.40 秒的 409 個位置，沒有加入雜訊。軌跡由我們設定的答案生成，所以能檢查求解器是否真的找回答案。

## 2. 每一幀都有一條方程式

模型是：

```text
重建位置 = 固定起點 + 第一條進度 × 第一條位移 + 第二條進度 × 第二條位移
p_hat(t) = p0 + s1(t) d1 + s2(t) d2
```

時間已知，所以每一幀的兩個進度都已知。只有兩條位移的 XYZ 分量未知。

以 X 方向為例：

- 第 1.20 秒，進度為 `s1 = 0.5, s2 = 0`，原始 X 是 `0.35`。因此 `0.5 d1x = 0.35 - 0.20 = 0.15`。
- 第 2.20 秒，進度為 `s1 = 1, s2 = 0.5`，原始 X 是 `0.44`。因此 `d1x + 0.5 d2x = 0.44 - 0.20 = 0.24`。
- 這兩條式子可以解得 `d1x = 0.30, d2x = -0.12`。

程式使用全部 409 幀，不只使用這兩個時間點。Y、Z 方向使用相同的進度，各自求解。

## 3. 把方程式排成矩陣

```text
S：409 × 2，每列是一幀的 [s1(t), s2(t)]
D：  2 × 3，每列是一條位移的 [dx, dy, dz]
Y：409 × 3，每列是原始位置減去固定起點

S @ D ≈ Y
```

`@` 是矩陣乘法。求解器找出使所有位置差異的平方和最小的 `D`：

```python
target = positions - initial
displacements, _, rank, singular_values = np.linalg.lstsq(
    basis, target, rcond=None
)
```

已知答案沒有傳給求解器；只有最後驗證時才比較答案。生成軌跡使用逐條位移相加，求解器使用矩陣運算。進度函數另有手算數值檢查。

## 4. 從位移得到 goals，再重建

```python
goals = initial + np.cumsum(displacements, axis=0)
reconstructed = initial + basis @ displacements
```

第一個 goal 是起點加第一條位移，第二個再加第二條位移。此例的答案為：

| 參數 | XYZ |
|---|---|
| 第一條位移 | `(0.30, 0.10, -0.05)` |
| 第二條位移 | `(-0.12, 0.20, 0.08)` |
| 第一個 goal | `(0.50, 0.00, 0.35)` |
| 第二個 goal | `(0.38, 0.20, 0.43)` |

goal 是位移累加的參數，不要求軌跡在某個指定時間通過每個 goal。

## 5. 驗證成功案例

驗證的是位移、goals 和完整重建軌跡，不只是目視曲線重合。三者的逐分量絕對差都必須小於 `1e-12` m；這是本例的數值檢查容許值，不是人類動作的品質門檻。

本次結果：

- 位移的最大分量誤差約 `1.11e-16` m。
- 三維位置 RMSE 約 `1.81e-16` m。
- 矩陣有兩個線性獨立的欄，rank 為 2，可以唯一求出兩條位移的最小平方解。
- 條件數約 3.85；本例沒有出現明顯的數值病態。

這種精度是預期結果，因為資料直接由同一類模型產生，沒有雜訊。它不是對真實資料重建精度的預測。

## 6. 刻意建立無法唯一求解的案例

讓兩條位移都在 0.20 秒開始、2.20 秒結束。此時每一幀的兩個進度完全相同：

```text
s1(t) = s2(t) = s(t)
p_hat(t) = p0 + s(t) × (d1 + d2)
```

資料只能決定位移總和，無法分辨兩條位移各是多少。矩陣的 rank 變成 1，而不是 2。

原本兩條位移的總和是 `(0.18, 0.30, 0.03)`。最小平方法在這個例子返回兩條相同位移 `(0.09, 0.15, 0.015)`；它們能重建相同軌跡，但不是原本設定的兩條位移。程式也另外驗證另一組不同位移能產生相同軌跡。

所以：重建誤差很小，不代表辨識到唯一或正確的動作分解。即使 rank 完整，如果兩個欄非常接近，求出的位移也可能對資料微小變動敏感；真實資料還要檢查條件數與穩定性。

## 7. 執行與檔案

在 `research/motion_decomposition/` 目錄、既有 WSL Python 環境執行：

```bash
python3 -m unittest discover -s tests -v
python3 -m motion_decomposition.step1_known_motion
```

- [固定時間求解器](../motion_decomposition/fixed_times.py)：建立進度矩陣、解位移、計算 goals 與重建誤差。
- [已知答案實驗](../motion_decomposition/step1_known_motion.py)：生成資料，執行成功及不可辨識案例，保存結果。
- [測試](../tests/test_fixed_time_fitting.py)：手算進度、位移恢復、不可辨識性、非精確模型資料的最小平方條件與非法輸入。
- [比較圖](../results/step1_known_motion/known_motion_fit.png)：上方是兩條進度，下方是 XYZ 已知軌跡與重建軌跡。
- [數值紀錄](../results/step1_known_motion/summary.json)：記錄已知及求解參數、rank 和誤差。
- `results/step1_known_motion/trajectories.npz`：保存矩陣、時間、軌跡及位移。

本步固定起點，沒有額外加終點約束，也沒有擬合時間。終點在成功例中吻合，是因為資料符合精確模型。真實資料是否要強制終點吻合，必須在下一步實驗前明確決定。
