# 第三步：觀察速度低點，建立待檢查的候選

本步完成原始速度的計算、局部低點偵測與圖形觀察；尚未建立最終邊界篩選規則。橘色點是候選，不是已確認的動作單元邊界或 goals。

## 1. 為何觀察速度低點

教授指出，單次 minimum jerk 運動內部也會出現加速度峰值，因此不能把加速度峰值直接當成動作之間的切點。速度低點是另一種候選線索：有些減速或停頓可能靠近動作交接處。

這仍是假設。重疊運動的交接不一定完全停止；持續轉向也不一定出現低速。需要檢查哪些低點有用、哪些只是微小變化，不能直接把每個低點當成一個單元。

## 2. 這次程式做了什麼

1. 沿用同一段 6,086 幀的原始全域手腕位置與時間。
2. 對完整片段的 XYZ 位置做數值微分，得到速度向量，使用 `numpy.gradient(..., axis=0, edge_order=2)`。
3. 計算速度向量的長度：`speed = sqrt(vx² + vy² + vz²)`，單位 m/s。它不帶正負號，與單一方向的速度不同。
4. 找局部低點：候選值必須嚴格低於左、右鄰居。若連續數幀完全相等且低於兩側，記錄整個平臺，顯示時採第一幀。
5. 保存所有候選，畫出 XYZ 位置與速度大小。速度先由完整片段計算，再截取局部顯示。

沒有平滑、速度門檻或最小時間間距。片段首尾不作為內部極小值輸出；後續分段時是否保留端點，是另一項決策。

## 3. 怎麼讀圖

- 上方三格是原始 XYZ 位置，藍色曲線；橘色點標出候選時間對應的位置。
- 最下方黑線是三維速度大小；橘點才是由這條曲線找出的局部低點。
- 同一時間的橘點會出現在四格，但上面三格的橘點不代表各座標的局部極值。
- 局部低點只代表「比左右鄰居小」，不是「速度接近零」。

先前已觀察過的三個區間用於這次圖形檢查：8–12 秒的相對平穩區間、17–23 秒的變化區間，以及 31–33 秒包含短位置跳動的區間。它們不是隨機或具代表性的統計抽樣。

## 4. 實際觀察

完整片段有 1,386 個原始局部低點，沒有完全等值的低點平臺。另一種獨立的向量化鄰居比較，也找出相同的 1,386 個候選。

相鄰候選的中位時間間隔約 0.0333 秒，最短約 0.0167 秒；1,385 個間隔中，有 1,353 個小於 0.1 秒。這裡的 0.1 秒只是對照先前設定的描述數值，沒有拿來篩選候選，也沒有宣稱它是合理的動作時間尺度。

| 顯示區間 | 候選數量 | XYZ 各自位置範圍（cm） |
|---|---:|---|
| 8–12 秒 | 135 | 約 1.495、3.080、1.146 |
| 17–23 秒 | 124 | 約 29.017、33.477、41.807 |
| 31–33 秒 | 46 | 約 7.156、34.019、23.115 |

8–12 秒的位置範圍相對小，但仍有大量速度低點，顯示直接以未處理的數值極小值分段會產生很多細碎候選。圖中小幅波動的物理來源尚未確認，不能直接全部稱為雜訊。

17–23 秒的圖提供兩種不同的例子：

- 19.950 秒的候選速度約 0.00772 m/s，接近零，且位置曲線在下降後變得較平緩，值得作為邊界候選進一步檢查。
- 21.333 秒的候選速度約 1.51950 m/s，仍在快速運動中。它雖然比左右鄰居低，不能因此當成自然動作之間的停頓。

全片速度最高的局部低點在 42.025 秒，約 2.07948 m/s。這明確說明「局部低點」與「低速」不同。

31–33 秒則同時有位置短跳動與較大範圍的移動。例如 31.817 秒的速度低點約 1.17587 m/s，仍位於一段快速移動中。單純鄰居比較會在大的速度隆起上也找出低點，尚不足以建立動作單元。

## 5. 目前的結論與待做決策

速度低點提供可以檢查的候選，但原始候選過密，而且不是每個候選都低速。本步沒有把它們轉成 1,386 個 goals，也沒有以這些候選重新擬合軌跡。

接下來應先一起看圖，再決定如何辨認較大時間尺度的減速／停頓。可能需要研究平滑、低點明顯程度、候選合併或持續時間，但目前沒有選定方法或門檻，也沒有驗證其效果。

此外，這裡使用全域手腕座標，速度包含身體與手腕的共同移動。速度低點也會依參考座標而改變；目前沒有改用相對身體座標。

原本不固定終點的第二步實驗已移除；替代的固定起終點真實資料比較已完成，詳見 [第二步](fitting_step2_fixed_endpoints.md)。本步只分析速度候選，尚未用這些候選估計新的啟動與完成時間。
