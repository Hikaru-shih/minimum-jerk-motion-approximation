# 真實資料短片段檢視

先選同一段手腕資料的 18–21 秒，作為時間擬合的除錯片段。根據先前 17–23 秒的觀察，這段包含較平穩的區域與一次明顯的位置變化；不是隨機抽樣，也不能代表整段動作。

執行（從本研究目錄）：

```bash
python3 -m motion_decomposition.step5_inspect_real_window
```

[位置與速度圖](../results/step5_real_window/position_velocity.png) 左側依序為 XYZ 位置、與起點的直線距離；右側為 XYZ 速度和速度大小。距離不是累積路徑長度。紅點標出裁切端點。

範圍是原始第 2160–2520 幀（索引從零開始、包含兩端），共 361 個樣本，120 Hz，經過時間 3 秒。保存原始全域 XYZ，不平滑、不重新取樣；相對時間另存供後續使用，並未改動位置。

速度先在完整片段上以 `numpy.gradient(..., edge_order=2)` 計算再裁切，避免把新的裁切端點當成完整資料端點。只在短段內微分會使端點速度有所不同，本次最大向量差約 0.04782 m/s。後續比較必須明確採用相同的微分規則。

起點和終點速度大小約 0.03169、0.07311 m/s，整段最高約 1.08662 m/s。這些端點沒有被確認為動作邊界。若所有 minimum jerk 分量都在短段內開始並完成，模型的解析端點速度為零，因此即使位置端點固定，也存在速度邊界不匹配；不能把固定位置誤稱為符合全部邊界狀態。之後需單獨檢查此限制，不能靠增加分量保證消除。

程式已檢查樣本數、連續幀、取樣間隔、有限值，以及輸入檔案前後 SHA-256 不變。[數值摘要](../results/step5_real_window/summary.json) 與 [資料](../results/step5_real_window/window.npz) 保存在獨立結果目錄。

本步尚未設定分量數量、產生本短段初猜、重建、最佳化時間或加入抵銷懲罰。下一步才是在這段資料上固定實驗用分量數量，比較只擬合位移和同時擬合時間的結果；不能將它當成全片段驗證。
