# 尺度與權重敏感度

## 先固定比較規則

固定同一段 18–21 秒資料、K=4、起終點、最短持續時間 2/120 秒、既有十組初猜與每次 `max_nfev=1000`。權重預先指定為 `0、1e-7、3e-7、1e-6、3e-6、1e-5、3e-5、1e-4`，長度尺度 L 固定 0.3 m。

重用先前 0、1e-6、1e-4 的 30 組保存結果，另外執行五個新權重各十組，共 50 組新求解。沒有額外重跑舊條件、暖啟動或將初值改成上一個權重的答案。重用時核對設定與初始時間陣列一致；原結果不覆寫。

每個權重各自依總代價選成功停止且端點合格的解；不同權重的總代價不是同一目標，不拿它們直接排名。此實驗沒有以結果反過來宣告某個權重最好。

## 為什麼不把尺度和權重分開掃描

目前代價為：

```text
J = mean ||p_hat-p||^2
    + lambda/N * sum_n sum_i<j [(T^2/L)*max(0,-v_i dot v_j)]^2
```

展開後，對同一觀測時間範圍 T，懲罰前的係數包含 `lambda/L^2`。把 L 乘 c、lambda 乘 c²，整個目標函數相同。只改 L 而固定 lambda，相當於改有效懲罰權重，不是另一個獨立機制。

因此先固定 L、比較 lambda 比較清楚。L=0.3 m 仍是沿用人造實驗的指定尺度，不是已根據真實人體或量測誤差選出的尺度；目前也不宣稱同一 lambda 可不經評估套用到所有動作。

若只是把公尺換成公分，必須連位移、位置和 L 一起乘 100。此時位置與懲罰殘差都乘 100，總代價乘 10000，lambda 不必改。若把時間單位從秒換成毫秒，T 和分量時間同步改變，T² 會補償速度內積的時間單位變化。這些是公式的尺度關係，不代表有限精度最佳化在所有單位下都會完全走相同路徑。

## 發現與限制

在 1e-7 到 1e-5 的已測點，位移長度與反向代價隨權重增加而下降，位置誤差逐步上升。速度誤差不完全單調，因為沒有直接最佳化速度。

從 1e-5 到 3e-5，選中參數出現較大變化。以先前 lambda=1e-6、index 7 為參考，3e-5 選中解對齊後的最大結束時間差約 1.250 秒，分量形態也轉向另一群。這不是只有分量標號交換：使用前一步的 24 種配對、按解析速度差最小化後，差異仍存在。

觀察到的是有限權重點、有限初猜下的選中解變化，不是連續追蹤全部解分支，不能宣稱已找到精確切換權重或證明真正的數學分岔。也不能證明每一列都是全域最優。

零權重的九個未合格結果都因用完求解預算而停止，位置誤差較低但分量巨大；只有一個合格解能入選。因此不能把零到正權重的圖線下降解讀為懲罰降低了位置目標的全域最小值。這個求解預算限制仍保留，沒有替零權重額外加次數。

最小正權重在本表的位置誤差最低，不表示它最適合分量解釋；較大權重的分量小，也不表示較符合真實動作。先前已知答案實驗顯示懲罰會抑制真正的反向成分，因此沒有單靠本表選權重的充分理由。

入口 `step7_weight_sensitivity.py` 先核對快取設定，再對新權重共同求解，最後按固定規則選解並配對到原參考分量。三項新增測試驗證 L 與 lambda 的耦合、長度單位與時間單位變換關係，共 43 項研究測試通過。程式確認重建公式、固定端點、總代價相對初值及來源雜湊不變。

從研究目錄執行：

```bash
OPENBLAS_NUM_THREADS=1 python3 -m motion_decomposition.step7_weight_sensitivity
python3 -m unittest discover -s tests -q
```

本步完成權重敏感度的固定條件比較，尚未自動選權重、分量數或驗證其他片段。下一步可先固定一組明確的尺度規則與預定權重條件，對另一段資料做同樣比較，檢查上述現象是否重現；在此之前不能把目前選中條件稱為最終方法。
